# 萌卡 NT v1.5.11

本版本修复 QQ MSF 长连接被对端关闭后账号直接离线的问题。框架现在会对已在线账号的临时网络断开执行受控恢复，并继续对 W21、S26、主动离线和版本限制保持强制失败策略。

## 账号连接稳定性

- 已在线账号遇到 TCP EOF、连接重置或临时网络中断时，不再立即显示离线，而是进入自动恢复状态。
- 重连不是只恢复 TCP：新连接会重新执行 ECDH 与 InfoSync 鉴权，再启动心跳、票据刷新、状态上报、空间未读、资料刷新和其他在线生命周期。
- 每个账号同一时间只允许一个重连任务，避免一次断线事件触发并发登录和重复注册。
- 自动重连最多尝试 5 次，使用 0、2、5、10、20 秒的退避间隔；达到上限后才按网络异常离线。
- W21、S26、缓存明确失效、框架版本过低、主动离线与账号删除不会进入自动重连，仍按原安全流程处理。
- 重连过程中若 InfoSync 明确判定缓存失效，会立即停止重试并提示重新登录，不会用无限重试掩盖身份问题。

## 构建与外发

- Windows AMD64、Linux AMD64、Linux ARM64 继续使用同一套框架前后端构建。
- 正式二进制不再写入私有构建工作区的 Git 提交标识与 dirty 状态。
- 本次没有新增或删除插件 API，公开 SDK 仍为 85 个 action 与 5 类事件，无需插件适配。
- 外发包仅包含框架运行文件与前端资源，不包含源码、数据库、日志、环境文件、密钥、APK、QSign 或算法服务。

## 验证情况

- Go 全量测试与 `go vet` 通过。
- 前端 45 项业务与布局测试、生产构建通过。
- 开发文档生产构建通过。
- 测试环境两个 QQ 均通过缓存 InfoSync 上线。
- 对一条真实 QQ MSF 连接执行故障注入后，账号约 1 秒内首次重连成功，未出现 W21/S26，也未被错误标记为离线。
- 三平台包完成架构、版本、执行权限、敏感文件和构建元数据审计。

## 升级说明

1. 停止旧版框架并备份框架目录，尤其是现有 `data` 目录。
2. 解压对应平台安装包，替换程序与 `public` 前端资源。
3. 保留原有业务数据、配置、插件和运行目录，不要使用新包中的初始化数据覆盖现有数据。
4. 启动后确认账号缓存登录和插件连接恢复正常。
