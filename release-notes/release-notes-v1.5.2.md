# 萌卡 NT v1.5.2

## 更新

本次版本完成插件扩展协议 v2、官网发布审核和框架插件市场的联动升级。插件仍通过正向或反向 WebSocket 传输业务数据，同时增加最小权限、生命周期、配置和可选 HTTP 适配能力。

### Manifest v2 与自动权限识别

- 官网发布插件时会从各平台安装包中的 `mengka-plugin.json` 自动识别调用 API 和订阅事件，不再要求开发者在网页中重复选择。
- Windows 与 Linux 安装包的 `capabilities.actions`、`capabilities.events` 必须保持一致，避免不同平台获得不同权限。
- 插件市场安装前会再次校验 Manifest 与审核授权快照；安装包缺少清单、仍使用 Manifest v1 或申请额外权限时会停止安装并保留原版本。
- 市场服务按审核结果限制 action 和事件投递。已有手工正向/反向 WebSocket 服务继续保持原兼容策略，不会在升级后突然失去权限。

### 配置与敏感信息保护

- Manifest v2 可通过 `configuration.schema` 声明插件配置项，由框架统一校验和保存。
- 普通配置与敏感值分文件保存；敏感字段不会通过查询接口返回，也不会写入普通配置文件。
- Manifest v2 不再向插件进程提供明文令牌环境变量，插件应读取连接文件或权限受限的令牌文件。

### 可选 HTTP Webhook

- 管理员可以为指定插件服务开启 HTTP Webhook、配置 Hook 白名单并轮换独立访问密钥。
- Webhook 默认关闭，启用后仍通过原 WebSocket 连接投递，不会绕过 action 和事件授权。
- 密钥只在轮换时返回一次，数据库仅保存摘要；同时可生成对应服务的 OpenAPI 描述。

## 新增

### 生命周期与插件控制

- 市场托管插件可接收启动、停止、重启和配置变更生命周期通知。
- 新增插件服务启动、停止和重启接口，便于在管理端受控维护独立插件进程。
- 插件可在现有 WebSocket 连接中注册命令、管理菜单和周期任务；断开连接后注册内容自动失效，不会遗留后台任务。
- 市场托管服务保留较高优先级，托管进程不可用时仍可回退到在线的普通 SDK 连接。

## 升级说明

- Windows 10/11 64 位：下载 `mengka-nt-v1.5.2-windows-amd64.zip`。
- Linux x86_64：下载 `mengka-nt-v1.5.2-linux-amd64.tar.gz`。
- Linux ARM64：下载 `mengka-nt-v1.5.2-linux-arm64.tar.gz`。
- 升级前建议备份 `data` 目录，完整解压新版并替换程序与前端资源后启动。
- 手工创建的正向/反向 WebSocket 服务无需修改；通过插件市场发布或更新的旧插件必须先把安装包升级为 Manifest v2。

## 修复

### Linux 多架构安装修复

- 插件市场现在按服务器的系统和架构精确选择构件，Linux ARM64 不再误下 x86_64 安装包。
- GitHub/Gitee Releases 同时提供 amd64 与 arm64 附件时，框架会自动选择匹配版本，无需用户手工选择架构。
- 启动市场插件前会校验包内 ELF 架构；误装时返回明确提示，不再只显示 exit status 126。
- 2026-08-22 早期下载过 v1.5.2 的用户请重新下载对应附件，本页三个安装包已包含此修复。
