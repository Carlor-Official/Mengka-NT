# 萌卡 NT v1.4.6

## 新增

- 管理端新增独立的“用户”“卡密”“商品”“支付”入口，可统一管理用户、余额、QQ 归属、卡密、商品和在线支付配置。
- 用户端支持一个用户管理多个 QQ；每个 QQ 独立计算卡密有效期，并可通过卡密或在线商品续费。
- 新增扫码找回账号流程：框架内已存在的 QQ 可扫码确认归属，再在账号信息中续费，无需重复添加或修改运行中的账号。
- 新增商品与订单流程，商品可选择余额支付或在线支付；在线支付统一使用管理端支付配置。
- 网页登录权限改为用户维度控制，支持全局默认开关及单用户覆盖；用户停用后会同步关闭其全部 QQ 会话。
- 用户端 QQ 登录补齐滑块、身份验证和安全验证流程，并与框架端共用缓存登录与密码登录逻辑。

## 修复

- 修复刷新登录包参数和登录顺序异常可能引发的“身份验证失效 / W21”问题，恢复稳定的缓存登录与常规刷新流程。
- 修复 user 端 QQ 登录仅依赖缓存、无缓存时提示“缓存不存在”的问题。
- 修复在线时长把上线时间戳当作累计秒数，显示为数万天的问题。
- 修复框架内已有 QQ 使用卡密添加时错误要求账号离线的问题；现在会引导先扫码找回，再进行续费。
- 修复用户没有 QQ 时无法切换其他菜单的问题。
- 修复登录协议、设备指纹和登录节点在 user 端显示英文或与框架配置不一致的问题。
- 修复用户端商品、订单、余额与支付接口混用管理员会话的问题。
- 修复支付回调金额校验和重复回调处理不完整的问题，避免异常入账或重复发货。
- 修复账号配置保存后错误退出用户系统的问题；现在只清理对应 QQ 的登录缓存。
- 修复管理端账号缓存清理按钮未连接实际后端逻辑的问题。

## 优化

- user 端账号页统一为框架账号列表样式，补齐等级、消息、会话、环境、信息和操作列，以及搜索、分页与空状态。
- “编辑账号”“等级任务”“续费”统一收纳到每个 QQ 的更多菜单；账号配置改为弹窗编辑。
- 用户列表改为用户维度展示网页登录权限、余额与账号归属，避免把用户权限误解为单 QQ 配置。
- 卡密新增账号使用框架级权限创建；协议、指纹、节点均直接读取并使用框架配置。
- 数据库方案切换后会同步用户、商品、订单、支付等业务数据，减少新旧数据源切换造成的业务断层。
- 用户系统不再开放自行注册，账号由管理员统一创建和管理。

## 升级说明

- 直接替换程序文件即可，务必保留原有 `data` 目录和数据库配置。
- 升级后首次启动会自动补齐用户、商品、订单、支付及账号归属相关数据结构。
- 已存在于框架但尚未归属用户的 QQ，请在 user 端使用“扫码找回”，不要再次通过“添加账号”重复录入。
- 升级后建议让现有 QQ 正常完成一次缓存登录；如缓存已失效，user 端会自动转入密码登录及对应验证流程。
