# 萌卡 NT v1.6.2

v1.6.2 重点修复等级加速任务的执行与展示问题，并让“记住设备”真正落到电脑 QQ 客户端。管理端和 user 端使用同一套任务状态、补挂和定时执行规则，升级后不需要重新配置已有账号。

## 等级加速

- 重新整理电脑端和手机端页面，清晰展示距离下一等级、今日加速、任务完成进度及会员、日常、额外任务之间的计算关系。
- 每个可执行任务均提供独立开关，定时执行和批量补挂只处理已开启任务；不支持或未开启的任务保持可见但不可误选。
- “电脑 QQ 在线”加入批量补挂与定时执行范围，可与其他等级任务一起选择和执行。
- 修正“任务已完成但加速仍显示 0”“完成与待完成同时出现”等状态和统计问题。
- 补充视频任务执行链路，并优化 QQ 音乐金币兑换失败时的提示、重试与结果判断。
- 页面刷新不再反复整页闪烁加载，账号状态和任务开关会就地更新。

## 电脑 QQ 与记住设备

- “记住设备”改为默认且固定开启，不再要求用户额外选择。
- 旧数据中曾保存为关闭或空值的账号会自动迁移为开启。
- 恢复缓存账号时会检查 Linux QQ 登录窗口的“自动登录”状态；未勾选时由框架自动补勾，再继续恢复登录。
- 旧缓存若仍要求手机确认，框架会保留旧会话备查并自动重建新二维码会话，由当前在线账号完成授权，避免重启后反复卡在确认页面。
- 自动登录选项点击后会再次读取界面校验，未真正开启时不会误报成功。
- 电脑在线满任务时长后仍会自动确认任务、退出电脑 QQ 并释放运行资源。

## 初始化与运行稳定性

- 首次启动和非交互式 Linux 部署继续使用网页初始化，不再因终端无法输入而以 `EOF` 中止。
- 运行环境准备、数据库方案和容器能力检测保持自动化；不满足容器条件时继续使用 SQLite 与进程内缓存，不阻塞框架启动。
- 完善缓存登录、票据刷新、SsoInfoSync 与连接恢复之间的状态衔接，减少重启或短时网络异常造成的重复登录。

## API 与 SDK

- 新增 `get_music_ark`，用于生成带内容绑定签名的 QQ 音乐 Ark 卡片。
- Node.js 正向、反向 SDK 及示例同步至 120 个便捷方法。
- 官网 API 文档同步新增音乐 Ark 的参数、返回值和发送示例。
- 插件实际可调用范围仍由插件市场审核后的权限快照决定，升级不会扩大已有插件权限。

## 升级说明

1. 停止旧版框架，并备份现有 `data` 目录。
2. 下载对应系统和架构的 v1.6.2 外发包，完整替换程序与 `public` 前端资源。
3. 保留已有业务数据、插件及运行目录，不要用新包中的初始化文件覆盖现有数据库。
4. 启动后检查账号在线状态，并在等级加速页面确认任务开关与电脑 QQ 状态。
5. 已有缓存若仍要求手机确认，等待框架自动重建会话即可；无需反复手动确认。
