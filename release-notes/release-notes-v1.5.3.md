# 萌卡 NT v1.5.3

## 更新

本次版本集中修复首页入口、手机端布局、账号找回、设备签名参数、插件图片发送和插件市场安装问题，并同步完善官网插件发布与审核流程。

### 首页与登录入口

- 应用设置新增“首页默认入口”，可选择管理员端或用户端，配置位于邮箱设置上方。
- 直接访问框架首页时会按照设置进入对应登录页；管理员端和用户端的独立地址仍可正常使用。
- 首页不再自动弹出登录窗口，只有用户主动点击登录或业务需要重新认证时才显示。
- 登录完成后会回到原本准备访问的管理页面，避免认证后固定跳回概览。

### 插件市场与官网发布

- GitHub/Gitee Release 构件继续按照 Windows、Linux amd64、Linux arm64 精确识别和安装，并在 Linux 启动前校验 ELF 架构。
- 插件市场下载地址、运行架构和更新日志字段进一步统一，减少官网资料、审核快照与框架安装结果不一致。
- 官网发布流程会自动解析安装包 Manifest v2 的调用 API 与订阅事件，不再要求开发者重复勾选。
- 发布表单直接生成文章草稿和审核快照，审批人员及超级管理员的管理入口和权限判断已统一。

## 修复

### 手机端布局

- 账号、用户、商品、订单、卡密、交易、节点、指纹和插件操作日志统一使用手机端竖向记录卡片。
- 栏位标题保持横向单行完整显示，记录内容统一左对齐，不再需要左右滑动查看表格。
- 修复概览图表时间标签重叠、任务列表长文本与标签挤压等窄屏问题。
- 已覆盖 320、360、390 像素常见手机宽度，并增加自动化布局回归检查。

### 图片缓存修复

- 修复 Redis 未启用或暂时不可用时，插件图片上传成功但发送阶段提示“图片元数据未缓存”的问题。
- 图片元数据新增进程内 TTL 缓存兜底，Redis 正常时继续同步缓存，不改变现有插件 API。
- B站扫码登录等“先上传图片、再通过 file_id 发送”的插件流程无需更新插件即可恢复。

## 优化

### 账号找回与登录稳定性

- 账号找回改用独立扫码确认流程，不再临时拉起待找回 QQ 的离线登录会话。
- 扫码结果会校验确认 QQ 与待找回 QQ 是否一致；过期、拒绝和不匹配状态会明确提示。
- 完善设备指纹参数传递，确保登录、签名和安全验证使用同一套 Android ID、GUID、QIMEI、OAID、品牌、型号及系统信息。

## 升级说明

- Windows 10/11 64 位：下载 `mengka-nt-v1.5.3-windows-amd64.zip`。
- Linux x86_64：下载 `mengka-nt-v1.5.3-linux-amd64.tar.gz`。
- Linux ARM64：下载 `mengka-nt-v1.5.3-linux-arm64.tar.gz`。
- 升级前请停止框架并备份原有 `data` 目录。完整解压新包后替换程序与前端资源，不要用空数据目录覆盖现有运行数据。
- 本次未改变插件 WebSocket API；现有 Manifest v2 插件无需重新适配。
