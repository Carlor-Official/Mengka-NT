# 萌卡 NT v1.8.1

本版本基于已经完成测试环境验收的 1.8.0 现代管理端与 SQLite 运行边界发布，新增专属 Key 授权链路，并将官网、正向 SDK、反向 SDK 统一到 189 个公开 API。

## 专属 Key

- 管理员头像菜单新增“专属 Key”，支持首次固定绑定、查看绑定状态和受控解除。
- `send_packet` 与“QQ 宠物”分组的 25 个接口纳入专属 Key 范围，共 26 个受控 API；其他 API 继续按原方式调用。
- Key 与框架实例共同校验，有 Key 但实例不匹配时拒绝调用。
- 插件调用保留原业务 `params`，专属 Key 仅位于 action 信封层，不改写 `self_id`、`cmd`、`data`、`rsp`、`reserve` 等传输字段。
- 算法系统可按 Key 多选、编辑允许调用的 API，并记录用户、插件、框架实例、发送 QQ、发送内容和调用时间。

## API 与 SDK

- 官网、正向 Node.js SDK、反向 Node.js SDK 均同步为 189 个公开 API。
- Node.js SDK 增加专属 Key 信封兼容；框架已经绑定 Key 时，插件无需重复保存 Key。
- 恢复并纳入 25 个 QQ 宠物 API，保留原请求字段、响应结构和协议处理。

## 安全与运行边界

- 外发包继续使用本地 SQLite 与进程内缓存，不引入 PostgreSQL、Redis、旧用户门户、商城支付管理或 QQ 账号授权到期体系。
- 清理 QQ 音乐听歌上报模板中的历史抓包账号身份和过期访问令牌，改为使用当前登录账号的数据。
- 软件包不包含数据库、管理员配置、专属 Key、日志、源码或 Git 元数据。

## 前端修复

- 修复打开“关于”页面时，左侧菜单和顶部标签错误高亮“设置”的问题；父子路由现在优先匹配更具体的页面。
- 登录页新增“保存密码”开关，密码只交由浏览器密码管理器处理，不写入框架本地存储。
- 登录页新增“保持活跃长在线”开关；开启后使用滚动 30 天会话，关闭时继续使用原有 7 天会话。
- 长会话刷新令牌仍使用 HttpOnly、Secure、SameSite Cookie，续期轮换后保持原会话模式。

## 升级方法

1. 停止正在运行的萌卡 NT，并完整备份原目录中的 `data`。
2. 下载与操作系统、CPU 架构匹配的 1.8.1 软件包并核对 `SHA256SUMS.txt`。
3. 从 1.8.0 升级时替换程序和 `public` 前端资源；保留原有运行数据与管理员配置。
4. 启动框架并确认后台显示 1.8.1；需要使用受控 API 时，在管理员头像菜单绑定算法系统签发的专属 Key。

从更旧的大版本升级时建议使用新目录部署，不要用外发包中的初始文件覆盖现有数据库。真实 QQ 功能仍受账号状态、客户端协议和 QQ 服务端状态影响。
