# 擂台创建失败诊断（v2.3.1）

适用于 `get_level_tasks`、`execute_level_tasks` 及后台等级加速页面。此修改不增加公开 API 参数或响应字段，也不改变 1–99 随机分数规则。

## 查看失败阶段

新执行失败时，在目标账号的“近期日志”以及框架运行日志中查看 `擂台任务 stage=...`。日志记录固定阶段、失败分类、QQ 数字错误码及新房间确认/上传标志，不记录凭证、房间标识或原始响应。

- `arena_panel` / `game_selection`：创建前的面板查询或游戏选择失败。
- `create_baseline`：创建前的本人历史擂台查询失败，尚未发送创建请求。
- `create_request`：创建请求未获得可接受的响应；超时并不证明服务端未创建。
- `create_response`：创建响应无法解析或未通过新房间校验。
- `create_readback`：创建响应成功，但本人列表、房间详情或初始成绩未通过确认。
- `launch_metadata`：新房间已确认，后续小游戏启动信息查询失败。

准备和启动信息失败不再统称“擂台创建结果未确认”。旧每日记录若 `creation_sent=false`，查询时显示“擂台准备失败，未发起创建，今日不再尝试”；已发送的结果不明记录仍保留原提示。旧版本没有保存的失败阶段无法追溯补全。

## 创建后的读取延迟

成功创建后，如果新房间暂未出现在本人列表/详情，或详情暂缺房主，最多进行 6 次只读确认，每次间隔 500 毫秒。创建请求始终只发送一次。账号失效、取消、超时、QQ 拒绝、格式错误、房间不匹配或初始成绩异常都会停止，不重复创建或上传。

每日尝试记录不会被自动清除或重放。只能从当前新房间确认成功后继续执行，不能使用已有房间或“再次挑战”替代创建。

## 验证范围

延迟列表、延迟详情和延迟房主投影的回归测试覆盖有限重读；永久不可见、错误房主、错误房间、响应格式错误、取消、会话终止、创建超时及 QQ 拒绝覆盖停止边界。这些测试证明修复可处理相应场景，不能据此认定任意历史客户故障均由读取延迟导致。
