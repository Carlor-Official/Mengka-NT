# 擂台任务直接协议模式升级说明

这是 v2.3.0 相对 v2.2.3 的升级说明。2026-09-15 02:37，2082083 已在 Linux amd64 测试站通过一次标准 API 的 Go 直接协议任务验收：task80 未完成变为已完成，原始查询和管理刷新均为 status=1，每日记录 completed 且 creation_sent=true，没有运行游戏或新增 worker 工作目录。此前测试站的 11 分样本与同房本人读回由已部署控制器的成功门槛确认；v2.3.0 改为每次 1–99 随机整数，QQ 完成由独立 0x916e → 0x9172 刷新确认。Windows Go 只读认证已通过；Windows 与 Linux arm64 的完整任务未实测。此前 worker 验收保留为历史记录，

- 同步升级框架、管理前端与 SDK。`get_level_tasks`、`execute_level_tasks` 及共享任务管理 API 的名称、参数、返回外壳保持不变；不增加公开 `score`、`game`、`time` 参数。
- task80“创建小游戏擂台并取得成绩”改由框架 Go 协议链执行，不运行游戏、不启动外部 worker。仅支持方块冲刺 v6，每次在 1–99 中随机选择一个整数分数；不对外开放分数参数。
- 当前默认执行不读取旧 `MENGKA_ARENA_WORKER_CONFIG` 安装配置，无需为此任务安装 Python、Node、Chrome、Playwright、Babel 或配置任务 cgroup。旧 worker 文件可保留为回滚参考，升级不会自动清除旧依赖或修改服务设置；不要把旧安装开关当作当前任务计划开关。
- 升级前核对框架原有自动等级任务计划；新模式的 `available/executable` 表示框架执行能力，既有已启用计划可能按原调度器执行。需要暂停时，使用现有任务计划设置。当天持久尝试后 `can_execute=false`，仍允许保存次日计划。
- 保留现有数据库与每日 journal。更换二进制、模式、重启或退出后都不释放当天尝试资格；已完成任务不再创建。创建不确定或 300768 不重试、不复用旧擂台，分数上传不确定也不重放。
- 只有当前账号的新房初始空分、上传成功、同房本人本次随机分数读回、退出协议确认和独立 `0x916e → 0x9172` 返回 task80 完成全部成立，才报告成功。上传回包不能代替 QQ 最终入账。
- 缺少 `ilink_buffer` 是 QQ 登录凭证缺失。只有最终 `wx.login` 明确 `authorization_required` 才提示“微信未授权登录”，不从通用认证或网络错误推断。

安装者自行安排备份、停服与回滚；本说明不授权自动重启或部署。验收应先用原始查询和管理面板刷新核对当天状态，仅对未完成且没有当天 journal 的当前 Android 账号执行一次，并保留执行前后 QQ 状态与每日记录。不得为了验收删除历史记录或重复执行。


## v2.3.1 创建前失败恢复

v2.3.1 起，仅终态为 failed、creation_sent=false、原因为 creation_not_confirmed 或 metadata_failed、且当天未使用过恢复机会的记录，允许一次受控重试。再次执行前重新核验当前 QQ 面板与登录材料，在同一事务内完整归档旧记录并更换 attempt_id；已发出的创建、执行中、中断、未知结果及已恢复一次的记录不重放。attempted_today 仍如实为 true，本次能否执行以 can_execute 为准；客户端不自动重试。

本节更新此前“登记后均不可重试”的规则；无创建请求发出证明时继续保持原限制。不得删除历史记录或据此重放分数。
