# 本地管理员初始化与旧版迁移

框架管理员已经与萌卡 NT 官网用户系统解耦。全新安装在初始化页面输入管理员账号和两次密码即可完成初始化；账号和 bcrypt 密码摘要只保存在当前框架的本地数据库中。初始化与后续登录都不会把管理员凭据提交到官网，也不再接受官网个人令牌。

## 现有管理员升级

保留现有 `data/config.yaml` 和 `data/config.db`，不要删除数据库或重置 JWT secret。框架检测到旧版官网管理员后会进入本地管理员迁移页面，但默认禁止匿名转换，避免暴露在公网的初始化入口被抢先接管。

1. 在框架进程环境中设置 `MENGKA_ALLOW_LOCAL_ADMIN_MIGRATION=1` 并重启；
2. 打开初始化页面，创建新的本地管理员账号和密码；
3. 确认可以使用本地账号密码登录后，移除该环境变量并再次重启。

迁移只替换管理员身份：保留 QQ 账号、插件、节点和运行数据，清除旧官网管理员资料、加密个人令牌和已有管理员会话。所有设备都需要使用新本地管理员重新登录。

插件市场若设置了 `MENGKA_PLUGIN_MARKET_URL` 或 `MENGKA_PLUGIN_MANAGED_CATALOG_URL`，既有域名迁移规则仍按框架当前实现处理；这与本地管理员认证无关。

API 路径中的 api.mknt.net、uc.api.mknt.net 及插件签名数据中的 mknt.net/plugin-* 是既有协议命名空间，保持不变。
