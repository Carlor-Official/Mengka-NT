# 元宝等级任务

v2.5.1 在现有 `get_level_tasks`、`execute_level_tasks`、`get_level_task_panel`、`execute_level_task_selection` 中提供元宝 P 图任务，不新增独立服务。执行成功以 QQ 任务中心确认完成为准，不以元宝接口或图片生成成功代替。

设备分配由框架内部处理，不提供用户设备列表、设备编号参数或手动绑定入口。新账号按现有添加账号、登录流程，在密码登录前自动准备元宝身份；已匹配关系复用。缓存登录及在线会话不为元宝改写身份；授权或验证期间禁止更换设备。准备失败不阻断普通 QQ 登录，元宝任务返回不可用原因。需配套支持元宝材料与实例授权的签名 APK 和算法网关。

## 调用

保持原 SDK 位置参数：`api.forProtocol('android').execute_level_tasks(self_id, ['来元宝P图一次'])`。
v2.5.2 起：首次任务提交触发安全验证后，框架后台在原验证有效期内每分钟查询一次官方状态，通过后只续接原任务一次。本人仍需完成官方验证，但无需再回到框架告知。关闭页面不停止后台确认；重启不恢复旧验证，最长期限十分钟且不延长官方授权的更早到期时间。最终请用等级任务查询接口确认 QQ task83 已完成，不能把最初的验证响应视为任务成功。

已有显式继续参数仍保留供旧客户端使用，与自动确认共用账号执行锁和一次性暂停记录，不会重复续接；新客户端无需发送它：

```js
await api.execute_level_task_selection({
  self_id, client_type: 'android', tasks: ['来元宝P图一次'],
  yuanbao_verification_completed: true
})
```

查询只读取 QQ 任务和本地执行状态，不调用 SDK 或元宝登录。标题与 `center_task_id=83` 必须同时匹配。已完成时不再授权、提交对话或重复领取。`available` 为框架能力；`can_execute` 还受完成状态与持久暂停约束。

## 执行与停止

执行内容已按最新要求改为**内置萌卡 Logo＋变高清**，不再执行固定文本自我介绍。复用在线 Android 9.2.70 的 OpenSDK 授权及同设备原 SDK 材料：联合登录 → show/click 归因 → 图片上传凭证 → 上传 Logo（仅官方明确 `isUploaded=true` 时跳过）→ 素材解析 → batchCreate → updateModel → 带图片的 mashup P图 → 回读 QQ task83。提示词固定“图片1, 变高清”，不接收用户自定义图片、提示词或远程素材地址。

Logo 为仓库原始 512×512 PNG，内置文件 SHA256 为 `3789ad0c89cf5f8dee04cacb311fc4895d24affdd7f9de1c897bfde1e66b880d`。COS 上传单独使用不携带 App 会话与 Cookie 的客户端，禁重定向、禁自动重试；解析失败、上传结果不确定立即暂停。图片流必须完整结束并返回明确可用的处理后图片，文字、占位图、原图回显、拒答或断流不能成功。HTTP/SSE 成功不是任务完成，只有 QQ 明确 `is_done=true` 才成功。

图片流程在上传前读取官方公开活动配置，以同设备 AID 调用官方 `getDeviceFingerprintID`，将本次返回的设备上下文放入 `/api/landing/deeplink/v1/resolve` 的 `finger_print`。该值不是 QQ 指纹或 QIMEI，不改写账号配置、不复用手机缓存，仅在本次操作内使用；缺失或异常立即停止。随后只接受实机已核对的创作入口 `/creations`、新会话标记和完整活动结果；未知路由、升级要求和安全验证停止。活动 taskid 与 QQ task83 属于不同命名空间，不替换 QQ 验收条件。解析结果仅在内存使用，不复用手机抓包票据，也不把它当作任务完成。此前固定文本尝试的结果不作为本图片流程验收依据。

原生图片请求保留活动来源 `extra.HY164=deep_link`、`HY165=mashup`、`HY108=本次官方公开配置的原始入口`。这些字段来自同版本官方 App 的 P 图请求，不能用通用文本或模板入口的值代替；不传入其他账号的入口或解析票据。

每次 App 请求使用同一设备上下文内新取的材料，时间戳与签名绑定；不复用附件账号凭据，不使用空 AID 或旧 web 签名，不自动注册。WebView 归因材料与 App 原生 q36 分开，不能互相填补。

活动归因请求单独使用账号现有协议/指纹生成的 QQ WebView UA、官方任务入口 Referer、同源 Origin 和 Web 请求头；App 请求仍使用自己的请求头，两者不得互相透传会话材料。活动上下文缺失或入口不是受信任任务页面时不发请求。

Web 归因 token 使用官方 Web SDK 0.9.1 已离线对照验证的 QQ 桥接编码：从当前 QQ 会话的现有 QIMEI 快照构造 `lt.bridge`，不把原生 Q36 原文当 token，也不拿元宝 App 的 Q36 替代 QQ 身份。只运行本地编码，不初始化浏览器指纹 SDK、不联网注册、不更改账号指纹、普通 QQ 签名或 APK。token 仅在本次会话内存中使用，参与 show/click 的签名，不写日志；QIMEI 缺失或非法时在元宝授权前报错。官方编码一致不等于服务器接受或 QQ 入账，仍必须实测回读。

兼容性边界：元宝完成联合登录、建会话、设置模型和 SSE 解析，并不保证 QQ task83 入账。历史测试曾出现上游接口完成但 QQ 任务未完成的情况；不能因此忽略 QQ 回读或自动重复提交图片任务。

归因上报与任务入账分别判断。候选版对 `show/click` 的 HTTP 200、根数值码 43001、已识别简单响应结构且无验证/限流/鉴权提示的结果记录为 `rejected`，不自动重试上报，继续一次既定会话流程；这不表示 43001 已解决或归因成功。其他未知结构、错误、安全要求仍暂停，登录/会话/对话检查不放宽。日志仅含账号、阶段、状态、HTTP 与数字码，不包含上游消息或凭据；QQ task83 未确认完成时仍保留暂停。

安全验证使用官方返回的类型和入口，不推断滑块/人脸。后台确认只查询原挑战，官方明确通过后才能原上下文续接一次；待验证、查询异常或未知状态均不提交任务，查询异常仅在原有效期内等待下一分钟确认。验证上下文最长十分钟，仅保存在内存。重启、过期、换设备、换 QQ 连接后保留暂停，不自动重新授权。对话阶段的验证、拒答、超时和 QQ 未确认完成均停止，不自动重放。旧实验版本的持久暂停不会自动启动轮询。

## 运维前置

对话流按 SSE 事件边界解析，兼容空数据保活、BOM、LF/CRLF/CR 和多行数据；`event:error` 即使没有 JSON 错误码也暂停。未知非 JSON 内容不当成成功。错误只记录固定事件/载荷类型、数字码和拒答标记，不记录对话内容；完整流仍须回读 QQ task83 才能确认任务完成。

已读取的流内出现非 JSON 事件后，仍检查后续完整事件，优先呈现官方错误或拒答，避免前置控制事件遮住实际失败；这不会追加请求或自动重试。没有明确业务错误时，未知事件仍阻止成功，诊断仅增加事件数量和 DONE 存在性。

已核对的控制帧 `speech_type: status/text`、空 plugin 标记和有界消息 ID/序号/追踪标记仅用于流解析，不作为正文、成功或 QQ 入账证据；`event:error` 优先于所有控制帧兼容规则。

候选实现的接口失败信息附带固定阶段 `stage`（联合登录、show/click 归因分别标识、创建会话、模型设置或对话）、HTTP 状态、受限数字错误码和 `error_shape` 结构类型。HTTP 为 `0` 表示尚未取得响应状态，并不证明请求没有发出；`code=missing/invalid/conflict` 表示未取得可安全展示的唯一数字码，不代表成功。`error_shape` 不是官方验证类型，不用于推断滑块或人脸。不会记录原始响应、错误文本、URL 查询参数、会话标识或设备材料。

归因失败另附固定枚举 `attribution_reason`（具体停止条件）、`message_class`（消息关键词分类）、`data_shape`、已知字段位图 `field_mask` 和未知字段存在性。它们不包含上游消息内容或未知字段名；消息分类只辅助定位，不等同于官方错误码定义，不会单独改变继续/暂停策略。

归因响应的额外标量元数据本身不再构成暂停条件；嵌套未知结构和错误/验证/鉴权/重试等控制字段仍保守停止。归因消息中的普通 `qimei token` 字样不等于账号登录鉴权失败，不能仅凭 `token` 子串阻断；明确的验证、限流或账号鉴权提示仍停止。此规则仅用于归因 43001，不用于联合登录或原生 App 接口。

HTTP 200、`code=0` 仍可能因响应结构未确认而暂停；不能据此自动放行或重试。该诊断仅补足定位信息，不改变解析成功条件、人工验证入口和持久暂停规则，也不能恢复旧失败请求未记录的错误码。

联合登录兼容官方错误模型的严格空默认对象 `{"code":"","message":""}`，但必须同时在同一响应节点具备非空字符串 `token/sessionToken` 和 `userId`，并继续检查业务错误、安全验证和注册状态。该限定兼容不适用于归因、对话或其他接口；非空错误、额外未知字段以及缺失会话均不会被忽略。诊断另附 `code_kind` 与会话字段存在性布尔值，不输出字段内容；`code=invalid` 仅表示数字码提取失败，不是腾讯业务错误码。

- 框架：默认沿用当前签名地址，以持久化框架实例身份自动申请独立短期授权。用户不填写共享密钥，也不选择设备。`data/framework-instance-identity.json` 必须随实例数据保留，不应复制给其他独立部署。设置 `MENGKA_YUANBAO_AUTO_AUTH=0` 可关闭自动授权。普通 QQ 签名地址不变。
- 现有签名网关：运维设置独立的 `QSIGN_YUANBAO_SECRET`（至少 32 字符）并显式启用 `QSIGN_YUANBAO_AUTO_ENROLL=1`。服务端密钥不得进入公开安装包；应持久保管，重启不轮换。代理需将 `POST /api/framework/yuanbao-grant` 和元宝任务路由交给签名网关，并保持现有网关访问规则。实例授权证明安装身份密钥持有，不代表 QQ 账号所有权或官方应用认证。
- 自动授权有效期一小时，按实例隔离操作并支持服务端撤销；每个实例最多两条活动操作，同一 QQ 同时一条。授权失效、设备变化及不确定结果会停止元宝操作，不影响普通 QQ 登录与签名。
- 仅隔离验收保留显式 `MENGKA_YUANBAO_SECRET` / `QSIGN_YUANBAO_SECRET` 和 `QSIGN_YUANBAO_ACCOUNTS` 白名单模式。`MENGKA_YUANBAO_BASE_URL` 仅覆盖元宝网关，必须为 HTTPS 或本机回环。不要向普通用户分发共享验收凭据。
- APK：使用同签名生产包及已审查 SDK 资源，由运维维护。普通开发构建默认不开启取材能力；部署需逐台验证包哈希、身份、路由和生产心跳，不能仅以安装命令返回成功验收。
- 同一元宝操作固定 SDK 连接、实例、租约及已应用设备摘要，QQ OpenSDK 授权签名与元宝材料均使用这个设备；无合格设备时在 QQ 授权前报错，进行中的请求不会悄悄切设备。任务请求复用账号内部绑定，设备失效不能在任务中途切换。正常密码登录前才可重新分配；不为元宝主动下线、重登、调整心跳或续票。

自动准备只在正常密码登录前进行：按账号分配合格设备，原子保存对应身份与内部绑定，并私下备份旧身份。已在线及缓存登录会话不迁移；元宝授权前仍核对当前 QQ 身份与材料，不能仅凭网关回执当作匹配。普通 QQ 签名路由不改动，不代表普通 QQ 签名也固定在同一物理设备。失败暂停不因设备准备而清除；不向客户端返回设备引用、算法设备列表或内部取票材料。
