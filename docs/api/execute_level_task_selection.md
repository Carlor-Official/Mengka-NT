# execute_level_task_selection

执行选定等级任务并返回刷新后的面板。

## 调用方式

```js
const result = await api.execute_level_task_selection({ self_id, client_type: 'android', tasks: ['去看免费小说'] })
```

## 参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `self_id` | number | 是 | 目标 QQ 账号 |
| `client_type` | string | 是 | 目标协议：`android` 或 `linuxqq` |
| `tasks` | string[] | 否 | 从 `get_level_task_panel` 中选择 `can_execute=true` 的任务标题；省略或空数组时，按已选计划或未完成任务筛选 |

## 返回值

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tasks` | string[] | 本次执行的任务标题 |
| `skippedTasks` | string[] | 已完成、不支持或付费等被跳过的标题 |
| `payload` | object | 执行后的等级任务面板 |
| `refreshed` | boolean | 执行后是否刷新成功 |
| `refreshError` | string | 刷新失败原因；成功时为空字符串 |

## 错误说明

- 目标账号需在线且 QQ 等级满足框架账号类型要求（free 至少 48 级，plus 至少 16 级，pro 无框架等级限制）。
- 单项失败后继续下一项，批次结束后汇总返回错误；整体取消或请求超时会停止后续执行。
- 批次报错时，其他任务可能已经完成；重试前查询任务面板。
- SDK 等待上限为五分钟；服务端整次请求预算为四分四十五秒。

## Android 9.2.70 元宝任务

现有等级任务入口支持 `来元宝P图一次`（`center_task_id=83`），仅 Android 9.2.70 可执行；Linux 不提供此任务。按 `available`、`can_execute` 和持久暂停状态判断是否能提交。查询本身不触发元宝授权或生成图片；执行成功必须由 QQ 返回 `is_done=true` 确认，结果不明不得自动重放。执行前由算法服务自动分配可用材料节点，框架用户无需手动选择或绑定设备。

产图完成后，QQ 可能延迟记账。此时显示“等待 QQ 确认”，不视为任务成功，也不再次登录或提交图片。当前 QQ 连接保持在线时，框架每分钟只读取一次任务状态，最多持续 45 分钟；后台查询结束、连接断开或重启后无执行器接管时，任务恢复待完成，可手动重新执行；下一次执行先查询 QQ，已完成则跳过。只有官方 task83 明确完成才显示已完成。

## 终止恢复（v2.7.9 起）

执行失败、取消、验证过期或执行器已退出后，任务释放回待完成，允许手动重新执行。升级遗留的暂停记录会自动清理，不需要用户修改数据库。清理仅恢复可执行状态，不代表成功，不更换指纹或清除 QQ 登录缓存，也不自动提交任务。仍在运行的执行器、有效验证和活跃 QQ 确认查询保持独占。后台计划不会把本次失败自动重放；插件也应由用户明确触发重新执行，避免按 `can_execute=true` 无限重试。
